# ⚖ 규정 제·개정 에이전트

**기관 실무 담당자의 내규 제정·개정을 돕는 웹 서비스**입니다. 기본 설정은 한국농업기술진흥원(KOAT)이며,
기관 프로필(`org_config.json`)과 내규 원문만 바꾸면 **다른 기관에서도 그대로** 쓸 수 있습니다([다른 기관에서 쓰기](#다른-기관에서-쓰기)).
기관 내규·유사 규정·상위 법령을 찾아 조문 초안을 쓰고, 신구조문대비표·제·개정 이유서·부칙·사전예고문까지
한 번에 만들며, 제·개정 절차를 단계별로 안내합니다. 작성 기준·절차·심의기준은 기관 프로필의 내규관리 규칙(KOAT: 「내규관리규칙」)을 따릅니다.

> 브라우저만 있으면 됩니다. 설치나 회원가입 없이 PC와 휴대폰에서 모두 쓸 수 있습니다.

---

## 왜 필요한가
- 지침을 새로 만들거나 고칠 때 무엇부터 해야 하는지, 어떤 문서가 필요한지 막막합니다.
- 유사 지침을 찾아 참고하고, 상위법 위임 범위와 조문 체계를 확인해 조문을 손으로 씁니다.
- 신구조문대비표·부칙을 수작업으로 만들고, 조 번호가 바뀌면 인용을 고칠 곳을 눈으로 찾아야 해서 빠뜨리기 쉽습니다.

## 이 에이전트만의 기능
- **심의 사전검토**: 초안을 기관 심의기준(KOAT: 「내규관리규칙」 제8조 — 필요성·적합성·통일성·명료성·체제·공개)별로 자동 점검하고, AI가 기준별 검토의견과 **상위법 위임 범위 초과 여부**를 써 줍니다. 결과는 「사전검토 의견서」로 저장됩니다.
- **인용 정정 자동 반영**: 조 번호를 옮길 때 이동표(예: `7→8`)만 넣으면 같은 내규 안의 인용 조 번호를 찾아 고친 정정안을 만들고, 버튼 하나로 수정안에 넣습니다. 「법령」·다른 내규 인용은 건드리지 않습니다.
- **용어·명칭 일괄 정비**: 직제 개편·명칭 변경 때 모든 내규에서 해당 말을 찾아 바꾸면서 **뒤따르는 조사(은/는·이/가·을/를·으로/로)까지 맞추고**, “제5조제1항 중 “○○”을 “△△”으로 한다.” 형식의 내규별 개정문, “다른 내규의 개정” 부칙, 통합 신구조문대비표를 만듭니다.
- **기관 맞춤 절차**: 절차 단계·질문·심의기준이 기관 프로필에서 나오므로, 기관마다 다른 내규관리 규칙을 그대로 반영합니다.

## 화면 구성

| 탭 | 할 수 있는 일 |
|---|---|
| 🆕 **제정** | 제정 목적·주요 내용·상위법 위임 조항을 넣으면 조문 체계와 표준 조문 초안 작성 |
| ✏️ **개정** | 개정 의도를 넣으면 조문 수정안과 신구조문대비표 작성, 인용 영향 분석·인용 정정 자동 반영 |
| 🧩 **일괄 정비** | 기관명·직위·부서명·내규명이 바뀌면 모든 내규를 찾아 바꾸고 개정문·부칙까지 작성 |
| 🏛 **상위법 영향** | 상위법 개정 조문을 넣으면 영향받는 기관 내규 조문을 찾아 개정 후보로 제시 |
| 🔍 **전체 점검** | 기관 내규 전체의 인용·명칭·조 번호 오류 점검 |
| 🗂 **절차 안내** | 「내규관리규칙」에 따른 단계별 할 일과 필요한 문서 |

### 🆕 제정
1. **기본 정보**: 내규명·종류·소관부서·시행일·제정 목적·주요 내용(한 줄에 하나, “제목: 내용”이면 조 제목으로 사용).
2. **상위법 위임 조항**: 법령명을 넣고 *조문 불러오기* → 근거 조문을 체크합니다(법제처 현행 법령). 직접 입력도 됩니다.
3. **유사 규정 참고**: 목적·주요 내용으로 기관 내규에서 비슷한 조문을 찾습니다. 체크한 조문은 초안 작성 때 참고합니다.
4. **조문 초안**: AI가 목적 → 정의 → 적용범위 → 본칙 → 세부사항 → 부칙 순으로 씁니다. AI 키가 없으면 **표준 조문 골격**을 만들어 줍니다. 결과는 바로 고쳐 쓸 수 있습니다.
5. **점검**과 **문서 세트**로 이어집니다.

### ✏️ 개정
1. 내규를 불러와 고칠 조문을 체크하고 **개정 의도**를 적습니다.
2. *수정안 작성*(AI) 또는 *선택 조문 직접 고치기*. 조문 **신설**은 「제N조의2」로, **삭제**는 번호를 남기고 “삭제”로 처리합니다(「내규관리규칙」 제6조).
3. **신구조문대비표**가 자동으로 만들어집니다. 바뀐 부분은 밑줄로 표시하고, 그대로인 항·호는 “(현행과 같음)”으로 줄입니다.
4. **영향 분석**: 고친 조문을 인용하는 같은 내규의 다른 조문, 별표·서식의 〈제N조 관련〉, 다른 내규의 「내규명」 제N조 인용을 찾습니다. 조 번호 이동표(예: `7→8`)를 넣으면 고칠 인용 표기를 제안합니다.

### 🏛 상위법 영향
상위 법령명, 개정된 조문(선택), 개정 전후 조문(선택)을 넣으면 기관 내규 전체에서 그 법령(시행령·시행규칙 포함)을 인용하는 조문을 찾습니다.
해당 조문을 직접 인용하거나 바뀐 용어가 들어간 조문을 **우선 검토**로 표시하고, *개정안 만들기*로 바로 개정 작업에 넘깁니다.

### 🔍 점검
- **조문 점검**: 조 번호 중복·결번·순서, 항(①②)·호(1.)·목(가.) 순서, 조 제목 누락, 이 내규에 없는 조문 인용, 현행 목록에 없는 내규명(명칭 변경 의심), 구 명칭(재단·이사장 등), 알기 쉬운 표기(각호→각 호, 당해→해당), 부칙·시행일, 별표·서식 인용.
- **전체 점검**: 기관 내규 전체에서 인용·명칭·충돌 오류를 한 번에 찾습니다.

### 🧩 일괄 정비
바뀌기 전·후 용어(예: `경영지원팀 → 경영관리팀`, `위임전결규정 → 위임전결규칙`)를 넣으면 모든 내규에서 찾아 조문별 변경 전후를 보여 줍니다.
정비할 내규를 고르면 **내규별 개정문, “다른 내규의 개정” 부칙, 통합 신구조문대비표, 정비 이유서**를 한글·Word로 저장합니다.

### 🧪 심의 사전검토 (제정·개정 공통)
기관 심의기준별로 ‘적합 / 확인 필요 / 보완 필요’를 판정합니다. 이유·주요 내용, 위임 근거, 인용 법령, 같은 이름·비슷한 내용의 내규(중복·상충), 표기·긴 문장, 조문 체제·시행일, 사전예고·협의 대상 여부를 점검하고, AI 키가 있으면 기준별 검토의견·위임 범위 검토·종합의견을 덧붙입니다.

### 📄 문서 세트
내규안(개정문)·제·개정 이유서·신구조문대비표·대국민 사전예고문·직원 의견수렴 공고·사전검토 의견서를 미리 보고, **복사·인쇄·한글(.hwpx)·Word(.docx) 저장**합니다.

### 붙여넣은 규정으로 개정
개정 탭에서 **원문 붙여넣기**를 고르면 등록되지 않은 내규나 다른 기관 규정도 바로 불러와 수정안·대비표·인용 정정·점검·사전검토를 할 수 있습니다.

### 🗂 절차 안내
내규 단계(규정·규칙·예규), 경미한 변경 여부, 국민 권리·의무 관련 여부, 부서 협의·부패영향·규제 해당 여부에 답하면
입안 → 협의 → 부패영향평가 → 사전예고 → 직원 의견수렴 → 자체 규제심사 → 심의 → 확정 → 시행 → 공개 단계와 필요한 문서를 맞춰 보여 줍니다.

## 관리자 안내

### 기술 구성
- **프론트엔드**: `index.html`(틀·AI 설정) + `assets/reg_agent.js`·`assets/reg_agent.css`(에이전트 화면). 빌드 과정 없음.
- **백엔드**: Flask `api_server.py`(법령 조문 조회·AI 호출·의미 검색) + `reg_agent.py`(`/api/regagent/*`) + `reg_upload.py`(내규 원문 등록·자동 커밋) + `reg_import.py`(원문 변환, 등록 화면·스크립트 공용).
- **배포**: Vercel(`api/index.py`가 Python 서버리스 진입점).

### 내규 원문 등록·갱신
**① 웹에서 — 📤 내규 등록(`/upload`)**: 실무 담당자가 제정·개정된 내규 파일(HWPX·DOCX·TXT·HTML·MD, PDF·HWP는 원본 보관)을 올리면 바로 에이전트에 반영됩니다.
- 쓰기 가능한 서버(로컬·VM)는 `regulations/`에 바로 저장하고, 이전본은 `regulations/.backup`에 보관해 **되돌리기**를 할 수 있습니다.
- Vercel 같은 읽기전용 배포는 `GITHUB_TOKEN`·`GITHUB_REPO`를 설정하면 **저장소에 자동 커밋 → 자동 재배포**됩니다.
- `REG_UPLOAD_TOKEN`으로 보호합니다. 자동 커밋을 켰는데 토큰이 없으면 업로드를 거부합니다.

**② 한꺼번에 — 일괄 등록 스크립트**(최초 구축·대량 갱신):
```bash
python scripts/import_regulations.py <내규 파일 폴더>           # 추가·갱신
python scripts/import_regulations.py <폴더> --reset            # 기존 데이터를 지우고 새로 구성
python scripts/import_regulations.py <폴더> --dry-run          # 변환만 시험
```
- 지원 형식: `.hwpx` `.docx` `.html` `.txt` `.md` (`.pdf` `.hwp`는 원본 보관만 — 본문을 쓰려면 HWPX·DOCX로 저장해 주세요).
- 파일명이 규정명이 되고, `인사규정(2025년 1월 일부개정).hwpx`처럼 괄호 안은 개정 정보로 들어갑니다.
- 결과는 `regulations/<규정명>/`과 `regulations_manifest.json`에 쓰이며, 저장소에 커밋하면 배포에 반영됩니다.
- 유사 규정 의미 검색 색인은 `scripts/build_embeddings.py`로 다시 만듭니다(`GEMINI_API_KEY` 필요, 선택).

## 다른 기관에서 쓰기
1. **기관 프로필**: `org_config.json`을 복사해 고칩니다.
   - `org_name`·`org_short`·`head`·`deputy`·`reg_word`·`rules_name`·`email_domain`: 초안·문서·안내 문구에 들어가는 기관 명칭
   - `notice_days`·`staff_days`: 사전예고·직원 의견수렴 기간
   - `drafting_rules`·`rules_summary`: AI 초안 작성 기준과 작성 기준 요약
   - `review_criteria`: 심의 사전검토 기준(id·제목·근거 조항·설명)
   - `procedure.questions`·`procedure.steps`: 절차 질문과 단계. 단계의 `when`(모두 일치)·`unless`(하나라도 일치하면 제외)로 조건을 줍니다.
   - `stale_terms`·`stale_words`: 점검 때 찾을 옛 기관명·직위명
2. **내규 원문**: `python scripts/import_regulations.py <폴더> --reset`으로 처음 한 번 넣고, 이후 개정분은 📤 내규 등록에서 올립니다(자동 커밋을 쓰려면 `GITHUB_REPO`를 그 기관 저장소로).
3. **(선택) 색인**: `python scripts/build_embeddings.py`
4. 같은 코드로 여러 기관을 운영하려면 저장소를 고치지 않고 환경변수 `ORG_CONFIG`·`REG_DIR`·`REG_MANIFEST`·`REG_VECTORS`로 기관별 파일을 지정하면 됩니다.

> 기관 프로필이 없으면 일반 기본값(○○기관·기관장)으로 동작하므로, 어느 기관이든 원문만 넣어도 바로 써 볼 수 있습니다.

## 프로젝트 구조
```
├── index.html                 # 화면 틀·AI 설정
├── assets/reg_agent.js·css    # 규정 제·개정 에이전트 화면
├── reg_agent.py               # 에이전트 API(/api/regagent/*)
├── org_config.json            # 기관 프로필(명칭·절차·심의기준) — 다른 기관은 이 파일을 고침
├── reg_import.py              # 내규 원문(HWPX·DOCX·TXT…) → 에이전트 데이터 변환
├── reg_upload.py              # 내규 원문 등록(/upload)·되돌리기·저장소 자동 커밋
├── upload.html                # 내규 원문 등록 화면
├── api_server.py              # Flask 서버(법령 조회·AI·의미 검색)
├── api/index.py               # Vercel 서버리스 진입점
├── reg_chunks.py              # 내규 원문 → 조문 단위 분할
├── hwpx_base.py               # 한글(.hwpx) 서식 베이스
├── regulations/               # 내규 원문(HTML) — 규정별 폴더
├── regulations_manifest.json  # 내규 목록·개정 정보
├── regulations_vectors.*      # 의미 검색 색인
├── scripts/                   # 내규 일괄 등록(import_regulations.py)·색인 생성 스크립트
├── run_local.py · requirements.txt · vercel.json
```
